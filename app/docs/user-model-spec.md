# 用户自定义 3D 骨骼模型：格式要求（草案）

> 状态：草案，尚未实现。需求是让用户用自己的 3D 骨骼模型替换待机页
> （`../qml/AwayPage.qml`）的默认模型。本文记录用户模型应符合的格式/标准，
> 以及实现这个需求还要做的事。
>
> 依据是现有实现：`AwayPage.qml` 用 Qt Quick3D 的 `RuntimeLoader` 运行时
> 加载 glTF，真机验证记录见 `../../qt3d-spike/docs/findings.md`。
> **只有标注"已验证"的条目在真机（dev1，rk3576/Mali-G52）上测过**，其余是
> 根据代码和 Quick3D 的行为推断的，定稿前需要实测。

## 硬性要求

| 项目 | 要求 | 依据 |
| --- | --- | --- |
| 文件格式 | glTF 2.0 的 `.glb`，贴图和缓冲区全部内嵌，单文件 | 已验证。`RuntimeLoader` 只支持 glTF 2.0 和 OBJ，而 OBJ 不带骨骼。FBX、VRM、BVH 等需用户先用 Blender 等工具转成 glb |
| 文件完整性 | glb 头里的长度字段必须等于实际文件大小 | 已验证。截断的文件会报误导性的 `No suitable reader found for the file format`（见 findings.md 第五轮） |
| 坐标与单位 | Y 轴朝上，单位为米，角色面朝 +Z | glTF 标准；页面相机在 +Z 方向看向原点 |
| 摆放与尺寸 | 脚底在 y=0，站在原点，身高约 1.5 m（现有相机的近似适用范围约 1.2–1.8 m） | 相机参数写死：环绕点 (0, 0.58, 0)，距离 3.55，按 CesiumMan 调的。做了"相机自适应"（见下）后可降为建议 |
| 蒙皮 | 标准 glTF skin，每个顶点最多 4 个骨骼权重 | 推断：Quick3D 只用第一组 `JOINTS_0/WEIGHTS_0`，多出的权重会被忽略 |

## 动画（TODO，待设计）

动画部分的要求**暂不定稿**。计划的方向是：一个模型带**多段动画**，由不同
的事件触发播放不同的动画，而不是现在的"单段动画无限循环"。这会直接改变
对用户模型的要求，所以等方案确定后再写。

现状（仅供设计时参考，不是对用户的要求）：

- `RuntimeLoader` 加载成功后自动播放 glTF 里自带的动画并无限循环，页面
  没有任何选择/切换动画的逻辑。
- 只验证过"文件内恰好一段骨骼动画"（CesiumMan）。文件里有多段动画时
  `RuntimeLoader` 的行为没测过。
- 生成的 Timeline / TimelineAnimation 从 QML 里够不到，现在靠
  `../core/TimelineLoopCloser.h` 从 C++ 侧找到它们来补循环起点和暂停。
  按事件切换动画大概率也要走这条路，或者换一种加载方式。
- `TimelineLoopCloser` 只补时间轴开头的空档，不修复首尾姿态不连续，
  所以目前循环动画需要首尾姿态一致。

待定事项：

- [ ] 有哪些事件，各自对应什么动画（待机、唤醒、聆听、说话……）
- [ ] 用户模型里的动画怎么和事件对应：按约定的动画名、按顺序，还是另附
      一份映射配置
- [ ] 哪些动画是必需的，缺失时的回退规则
- [ ] 哪些动画循环播放、哪些播一次；循环动画的首尾姿态要求
- [ ] 动画之间如何过渡（硬切还是混合），是否要求各段动画起止于同一个
      基准姿态
- [ ] 实测 `RuntimeLoader` 对多段动画的行为，确认能否单独控制每一段
- [ ] 关键帧插值方式（LINEAR / STEP / CUBICSPLINE）的支持情况
- [ ] 形变动画（morph target / 表情）是否支持——目前没测过，先不承诺

## 建议限制（未实测）

- **压缩扩展**：不要用 Draco、meshopt、KTX2/Basis。我们的 Qt 包
  （`v6.8.5-violoop3`）是否支持没验证过。贴图用 PNG 或 JPEG。
- **材质**：标准 PBR metallic-roughness。其他材质扩展可能被忽略或渲染
  不一致。
- **内嵌灯光和相机**：建议要求去掉。页面有自己的两盏灯，模型自带的灯光
  会叠加上去。
- **骨骼数**：只测过 CesiumMan 一个模型（shader 报 `boneCount=38`），
  6 小时稳定在 53 fps 左右。骨骼矩阵走纹理，没有硬上限，但更多骨骼的
  性能未知。
- **规模预算**：面数、贴图尺寸、文件大小的上限目前没有数据。CesiumMan
  属于很轻的模型，需要拿几个更重的模型在 dev1 上测出上限再写进本文。

## 实现这个需求还要做的事

- [ ] **加载路径**：现在模型编在 Qt 资源里（`../CMakeLists.txt` 的
      RESOURCES），要改成能从文件系统路径加载用户文件。
- [ ] **相机自适应**：用 `loader.bounds` 自动算环绕点和距离，这样"身高
      约 1.5 m、脚底在原点"可以从硬性要求降为建议。
- [ ] **校验与回退**：用户文件是不可信输入。加载前检查文件大小和 glb 头，
      `RuntimeLoader.Error` 时回退到默认模型。
- [ ] **测出规模预算**：见上面"建议限制"。
- [ ] **动画方案**：见上面"动画"一节。
- [ ] 用户怎么把模型放到设备上（上传入口、存放位置）——需求侧待定。

## 给用户的自检方法

模型能在 Khronos 的 glTF Validator 里无错误通过，并在任意标准 glTF
查看器里正确显示，基本就符合上面的硬性要求。动画相关的自检等"动画"一节
定稿后补充。
